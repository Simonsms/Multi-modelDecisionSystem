# 前端组件树与页面区块层级草案

**文档日期**：2026-04-08  
**文档目标**：基于已确认的中文 GUI 工作台母版页，继续细化到更接近开发可拆分粒度的前端组件树、页面区块层级和建议 props 草案  
**适用范围**：前端页面拆分、组件设计、接口联调准备

---

## 1. 核心判断

当前阶段不应该直接跳到写页面代码，而应该先把：

- 页面由哪些区块组成
- 区块由哪些组件组成
- 每个组件至少需要什么数据

这三件事拆清楚。

这样后续不管是：

- 你自己动手写
- 交给前端
- 让我继续往下出接口和组件草稿

都会顺很多。

---

## 2. 总体组件分层

建议把前端组件拆成 4 层：

1. `App Shell`
2. `Page Section`
3. `Business Widget`
4. `Primitive UI`

## 2.1 分层说明

### App Shell

负责全局布局：

- 顶部导航
- 页面容器
- 全局搜索
- 用户菜单

### Page Section

负责页面级区块：

- 左侧阶段栏
- 中间工作区
- 右侧建议栏

### Business Widget

负责业务语义组件：

- 模型摘要卡
- 候选方案卡
- 风险列表
- 证据卡

### Primitive UI

负责通用基础组件：

- Button
- Badge
- Card
- Tabs
- Divider
- Input

## 5. 核心组件职责

## 5.1 StageStepper

### 职责

- 展示完整阶段链路
- 突出当前阶段
- 展示已完成/当前/未开始/需关注状态

### 建议 Props

```ts
type StageStatus = "completed" | "active" | "pending" | "attention";

interface StageItem {
  id: string;
  label: string;
  status: StageStatus;
}

interface StageStepperProps {
  stages: StageItem[];
  currentStageId: string;
  onStageClick?: (stageId: string) => void;
}
```

## 5.2 SessionSummaryCard

### 职责

- 展示当前会话的最小上下文

### 建议 Props

```ts
interface SessionSummaryCardProps {
  title: string;
  projectName?: string;
  statusLabel: string;
  updatedAt: string;
  tags?: string[];
}
```

## 5.3 StageHeader

### 职责

- 显示当前阶段标题、说明和状态

### 建议 Props

```ts
interface StageHeaderProps {
  title: string;
  description: string;
  status: "进行中" | "已完成" | "待处理";
}
```

## 5.4 ModelSummaryPanel

### 职责

- 汇总当前阶段各角色模型输出

### 建议 Props

```ts
interface ModelSummaryItem {
  id: string;
  roleLabel: string;
  modelLabel: string;
  statusLabel: string;
  summary: string;
}

interface ModelSummaryPanelProps {
  items: ModelSummaryItem[];
}
```

## 5.5 CandidateOptionCard

### 职责

- 展示候选方案基本信息
- 与证据建立关联

### 建议 Props

```ts
interface CandidateOptionCardProps {
  title: string;
  statusLabel: "推荐" | "候选" | "较弱";
  summary: string;
  pros: string[];
  risks: string[];
  evidenceHint?: string;
  linkedSourceCount?: number;
}
```

## 5.6 ComparisonMatrix

### 职责

- 对多个候选方案按统一维度比较

### 建议 Props

```ts
interface ComparisonDimension {
  key: string;
  label: string;
}

interface ComparisonValue {
  optionId: string;
  dimensionKey: string;
  valueLabel: string;
  valueScore?: number;
}

interface ComparisonMatrixProps {
  dimensions: ComparisonDimension[];
  optionHeaders: { id: string; label: string }[];
  values: ComparisonValue[];
}
```

## 5.7 EvidenceCard

### 职责

- 展示单条关键证据

### 建议 Props

```ts
interface EvidenceCardProps {
  title: string;
  sourceType?: string;
  summary: string;
  tag: "可借鉴" | "谨慎借鉴" | "不建议借鉴";
  actionLabel?: string;
}
```

## 5.8 CurrentRecommendationCard

### 职责

- 展示当前建议
- 承载关键动作按钮

### 建议 Props

```ts
interface RecommendationAction {
  id: string;
  label: string;
  variant?: "primary" | "secondary" | "ghost";
}

interface CurrentRecommendationCardProps {
  title: string;
  statusLabel: string;
  summary: string;
  actions: RecommendationAction[];
}
```

## 5.9 RiskList / OpenQuestionList

### 职责

- 风险与待确认项分开展示

### 建议 Props

```ts
interface TextListItem {
  id: string;
  title: string;
  description?: string;
}

interface RiskListProps {
  items: TextListItem[];
}

interface OpenQuestionListProps {
  items: TextListItem[];
}
```

## 11. 建议的数据组织方式

建议页面不要直接吃后端原始对象，而是在前端做一层 ViewModel 转换。

例如：

```ts
DecisionWorkspaceViewModel {
  sessionSummary
  stageHeader
  modelSummaries
  candidateOptions
  comparisonMatrix
  evidenceItems
  recommendation
  risks
  openQuestions
}
```

### 原因

- 后端结构更稳定
- 前端显示更灵活
- 便于后续设计调整

---

## 12. 当前建议结论

基于当前母版页，前端拆分的正确方向是：

- 先按页面区块拆
- 再按业务组件拆
- 最后补通用基础组件

而不是反过来先堆一堆 UI 小组件。

如果压缩成一句话：

> 第一版前端最重要的不是“组件多细”，而是“页面区块、业务语义和数据入口要先对齐”。
